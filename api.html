API reference#

The names below are importable directly from the top-level package, for example gridops.Model, gridops.GoSolver and gridops.generate_config.

Model#

class gridops.model.Model(region, problem, solver_name='appsi_highs', solver_params=None, warmstart=False)[source]#

gridops production cost model.

Parameters:

  • region (str) – Geographic region. Supported: "west". Placeholders: "east", "ercot".

  • problem (str) – Problem type. Supported: "linear" (LP - economic dispatch). Placeholder: "mixed_integer" (MILP - unit commitment ).

  • solver_name (str) – Solver interface name. One of "appsi_highs" (open-source), "appsi_gurobi" (commercial) or "gurobi" (commercial). Default "appsi_highs".

  • solver_params (Optional[Dict[str, Any]]) – Optional dict of solver option name → value pairs. No defaults are imposed by gridops; pass every required option explicitly.

  • warmstart (bool) – If True, start each horizon from the previous horizon’s basis. With "appsi_highs" this forces solver="simplex" and run_crossover="off"; with "appsi_gurobi" it sets LPWarmStart=1 (or keeps a user-supplied 2); "gurobi" is switched to "appsi_gurobi". If False, HiGHS defaults to solver="ipm" with run_crossover="on" and its state is cleared between horizons, while Gurobi uses LPWarmStart=0 (APPSI only) and PreDual=1 unless set. Can be overridden per run in run(). Default False.

run(config_file=None, restart_day=None, n_days=365, horizon_hours=24, warmstart=None, allow_retry=True, max_retries=30, retry_n_seeds=1, retry_options=None, retry_backoff=True, restart_write_frequency=30, fresh_start=False, clear_restart=True, **kwargs)[source]#

Run the production-cost model.

Parameters:

  • config_file (str | None) – Path to the YAML configuration file.

  • restart_day (int | None) – Day whose restart file to use as starting point. None = resume from the latest available restart file (or start fresh).

  • n_days (int) – Total number of days to simulate. Default 365.

  • horizon_hours (int) – Hours for optimization horizon. Default 24.

  • warmstart (bool | None) – Overrides the instance-level warmstart setting for this run. None = use the value given to Model. See the class docstring for how each solver’s options are adjusted.

  • allow_retry (bool) – If True and a horizon fails, automatically attempt the retry logic before raising an error. Default True.

  • max_retries (int) – Maximum number of retry attempts before aborting. Applies to both HiGHS (algorithm and tolerance sweep) and Gurobi (random-seed sweep). Default 30.

  • retry_n_seeds (int) – Number of random seeds to try per solver algorithm in retry mode.

  • retry_options (Dict[str, Any] | None) – Dict overriding specific keys in HIGHS_RETRY_DEFAULTS. For example {"solver_list": ["simplex"], "simplex_strategy": [0, 1]} to only sweep simplex with two strategy values. None = use all defaults.

  • retry_backoff (bool) – If True and all retry trials fail, rewind to the prior restart file and retry from there. Default True.

  • restart_write_frequency (int) – Write a restart file every this many solved horizons. Default 30.

  • fresh_start (bool) – If True, delete all existing restart files and start the simulation from scratch. Default False.

  • clear_restart (bool) – If True, delete all restart files after all n_days have been solved successfully. Files are kept if the simulation fails before completion. Default True.

  • **kwargs – Forwarded to generate_config().

retry(config_file=None, solver_name='appsi_highs', n_days=365, horizon_hours=24, max_retries=30, n_seeds=1, retry_options=None, retry_backoff=True, restart_write_frequency=30, **kwargs)[source]#

Try alternative solver configurations after a failed horizon.

For HiGHS, builds a Cartesian product of algorithm choices, tolerance settings, and random seeds, then caps the total number of trials at max_retries.

For Gurobi, only varies the random seed (Gurobi’s algorithm selection is automatic). Generates up to max_retries random seeds.

After a successful retry the model reverts to the original solver settings and continues from the next horizon.

If all retry trials fail and retry_backoff is True, the model rewinds to the prior available restart file and tries again.

Parameters:

  • config_file (str | None) – Path to the YAML configuration file.

  • solver_name (str) – Solver interface name.

  • n_days (int) – Total number of days to simulate. Default 365.

  • horizon_hours (int) – Hours for optimization horizon. Default 24.

  • max_retries (int) – Maximum number of retry attempts before aborting. Applies to both HiGHS (algorithm and tolerance sweep) and Gurobi (random-seed sweep). Default 30.

  • n_seeds (int) – Number of random seeds to try per algorithm in the HiGHS sweep. The Cartesian product is still capped at max_retries.

  • retry_options (Dict[str, Any] | None) – Dict with retry search grid values. Uses HIGHS_RETRY_DEFAULTS for any missing keys.

  • retry_backoff (bool) – If True and all retry trials fail, rewind to the prior restart file and retry from there. Default True.

  • restart_write_frequency (int) – Write a restart file every this many solved horizons. Default 30.

  • **kwargs – Forwarded to the launch function.

gridops.model.HIGHS_RETRY_DEFAULTS: Dict[str, Any]#

Default search grid for HiGHS retry logic. Each key maps to a list of values to try; the retry method builds a Cartesian product per algorithm.

class gridops.solvers.GoSolver(solver_name='appsi_highs', solver_params=None)[source]#

Wrapper around Pyomo’s SolverFactory.

Validates the solver name, instantiates the solver, and applies any user-supplied options.

Parameters:

  • solver_name (str) – One of "appsi_highs", "appsi_gurobi", or "gurobi".

  • solver_params (Union[None, dict]) – Optional dict of solver-specific option name → value pairs. These are applied directly to the solver’s options dict. Pass None (default) to use the solver’s own built-in defaults.

go_solver#

The configured Pyomo solver object, ready to call .solve().

Examples

HiGHS solver with a time limit:

solver = GoSolver("appsi_highs", {"time_limit": 600})

Gurobi with a fixed random seed:

solver = GoSolver("appsi_gurobi", {"Seed": 123})
SUPPORTED = ('appsi_highs', 'appsi_gurobi', 'gurobi')#

All solver names accepted by gridops

Configuration#

class gridops.configuration.Config(generator_parameters_file, generator_matrix_file, line_to_bus_file, line_parameters_file, daily_hydro_maximum_file, daily_hydro_minimum_file, daily_hydro_total_file, nodal_solar_file, nodal_wind_file, nodal_offshore_wind_file, nodal_load_file, must_run_file, fuel_prices_file, storage_params_file, bus_to_storage_matrix_file, generator_outage_file, thermal_generators_file, lost_capacity_file, vlt_angle_file, mwh_file, slack_file, flow_file, duals_file, storage_soc_file, storage_discharge_file, storage_charge_file, restart_file_directory)[source]#

All file-path settings consumed by a gridops simulation run.

Every attribute is a string holding a file path (relative or absolute). The fields map directly to the YAML keys in the configuration file.

Input files:

  • generator_parameters_file (str) – CSV with generator parameters (name, typ, node, maxcap, etc.).

  • generator_matrix_file (str) – CSV mapping each generator to its node (rows = generators, columns = nodes, values = 0/1).

  • line_to_bus_file (str) – CSV mapping each transmission line to nodes via DC-OPF incidence (rows = lines, columns = nodes, values = -1/0/1).

  • line_parameters_file (str) – CSV with line parameters (line, reactance, limit).

  • daily_hydro_maximum_file (str) – CSV of maximum hourly hydro generation per node (rows = days, columns = nodes).

  • daily_hydro_minimum_file (str) – CSV of minimum hourly hydro generation per node (rows = days, columns = nodes).

  • daily_hydro_total_file (str) – CSV of daily total hydro energy budget per node (rows = days, columns = nodes).

  • nodal_solar_file (str) – CSV of hourly available solar generation per node (rows = hours, columns = nodes).

  • nodal_wind_file (str) – CSV of hourly available wind generation per node (rows = hours, columns = nodes).

  • nodal_offshore_wind_file (str) – CSV of hourly available offshore-wind generation per node (rows = hours, columns = nodes).

  • nodal_load_file (str) – CSV of hourly load per node (rows = hours, columns = nodes).

  • must_run_file (str) – CSV of constant must-run (e.g., nuclear) capacity per node (single row showing the capacities, columns = only nodes with must-run generators).

  • fuel_prices_file (str) – CSV of daily fuel prices per thermal generator (rows = days, columns = thermal generators).

  • storage_params_file (str) – CSV with storage-unit parameters (name, charge_rate, etc.).

  • bus_to_storage_matrix_file (str) – CSV mapping each storage unit to its node (rows = storage units, columns = nodes, values = 0/1).

  • generator_outage_file (str) – NumPy .npy file (dict) mapping each outage-group name to a list of generator names in that group.

  • thermal_generators_file (str) – CSV listing of thermal generators including nuclear units (used to compute must-run capacity adjustments).

  • lost_capacity_file (str) – CSV of hourly lost capacity per outage group (rows = hours, columns = groups). The first column must be Time (1-indexed integer).

Output files:

  • vlt_angle_file (str) – Parquet - hourly nodal voltage angles.

  • mwh_file (str) – Parquet - hourly generator dispatch (MWh per unit); also includes must-run nuclear output per bus (Type “Nuclear”).

  • slack_file (str) – Parquet - hourly unserved demand per node.

  • flow_file (str) – Parquet - hourly transmission line flows per line.

  • duals_file (str) – Parquet - hourly nodal locational marginal prices (LMPs).

  • storage_soc_file (str) – Parquet - hourly storage state-of-charge per storage-unit.

  • storage_discharge_file (str) – Parquet - hourly storage discharge per storage-unit.

  • storage_charge_file (str) – Parquet - hourly storage charge per storage-unit.

Other settings:

restart_file_directory (str) – Directory where cloudpickle restart files are written/read.

gridops.utilities.write_restart_file(dir, day, restart_data)[source]#

Serialize restart_data to a versioned cloudpickle file.

The file name encodes the day number and an auto-incremented version so that multiple restarts for the same day do not overwrite each other. Format: model_restart_file_day{DDD}_v{VVV}.pkl

Parameters:

  • dir (str) – Directory where the restart file will be written (must exist).

  • day (int) – Day index to encode in the file name. Pass 0 to skip writing (returns None immediately).

  • restart_data (Any) – Arbitrary Python object to serialize (typically a dict that includes the Pyomo model instance and accumulated result lists).

Returns:

Path or None – Path to the new file, or None if day is 0.

Raises:

Exception – If more than 101 versioned files already exist for day.

Return type:

Path | None

Western Interconnection#

These lower-level functions are called by gridops.model.Model.run(). They are documented for users who want to inspect or extend the optimization model.

gridops.west.launch.west_linear(config_file, solver_name='appsi_highs', solver_params=None, warmstart=False, n_days=365, horizon_hours=24, restart_day=None, save_restart_file=True, break_run=False, restart_write_frequency=30, fresh_start=False, clear_restart=True, **kwargs)[source]#

Run the U.S. Western Interconnection economic dispatch model.

Parameters:

  • config_file (str | None) – Path to the YAML model configuration file.

  • solver_name (str) – Solver interface to be used. Default "appsi_highs".

  • solver_params (None | dict) – Dict of solver options (option_name → value). None = solver built-in defaults.

  • n_days (int) – Total number of simulation days to process. The function stops after n_days * 24 / horizon_hours horizons. Default 365.

  • horizon_hours (int) – Length of each optimization horizon in hours. Default 24.

  • restart_day (None | int) – Specific day whose restart file should be used as the starting point. None = use the latest available restart file (or start fresh if none exist).

  • save_restart_file (bool) – If True, write a restart file periodically (controlled by restart_write_frequency). Default True.

  • break_run (bool) – If True, run exactly one horizon and return. Used internally by the solver-retry mechanism. Default False.

  • restart_write_frequency (int) – Write a restart file every this many solved horizons. Default 30.

  • fresh_start (bool) – If True, delete all existing restart files before starting the simulation so it always begins from scratch. Default False.

  • clear_restart (bool) – If True, delete all restart files after all n_days have been solved successfully. Files are kept if the simulation fails before completion. Default True.

  • **kwargs – Extra keyword arguments forwarded to generate_config().

Returns:

int – The 1-based index of the last successfully solved day (for compatibility with the Model class retry logic).

Raises:

  • RuntimeError – If the solver fails to find an optimal solution for any horizon.

  • AssertionError – If n_days is less than the implied start day from the restart file.

Return type:

int

gridops.west.linear.build_west_linear(data, horizon_hours=24)[source]#

Build and return a Pyomo ConcreteModel for the U.S. Western Interconnection linear economic dispatch problem.

The model is built once from the data dictionary returned by load_simulation_data(). Between solving horizons the mutable Horizon... parameters are updated in-place by _update_horizon_params() — no rebuild is needed.

Parameters:

  • data (Dict[str, Any]) – Data dictionary returned by load_simulation_data().

  • horizon_hours (int) – Number of hours in each optimization horizon (default 24 hours).

Returns:

pyomo.ConcreteModel – Fully instantiated model with all sets, parameters, variables, constraints, and objective defined. Mutable Horizon parameters are initialized to 0 and must be updated before the first solve.

Return type:

ConcreteModel
